# 02. 하네스 엔지니어링 3계층 방어 게이트 규범 (Harness Engineering Rules)

> **철학**: "문서는 확률을 낮추고, 게이트는 확정으로 막는다. 가장 중요한 것은 부탁이 아니라 차단으로 막는 것이다. 확률을 결정으로."

---

## 1. 규칙 위반 3유형 방어 아키텍처

| 위반 유형 | 발생 원인 | 확정 방어 장치 |
| :--- | :--- | :--- |
| **1. 규칙 부재** | 그런 규칙이 애초에 없었음 | 사고 발생 즉시 룰셋 영구 등록 및 사후 회고(Post-Mortem) 닫힌 루프 가동 |
| **2. 컨텍스트 유실** | 대화가 길어져 컨텍스트에서 밀려남 | 헌법(`CONSTITUTION.md`) 및 글로벌 룰셋(`alwaysApply: true`)에 영구 안착하여 지속 로드 |
| **3. 우회 시도** | 규칙을 알지만 모델이 임의로 다른 길로 감 | 문서가 아닌 물리적 게이트(Gate)로 확정 차단 |

---

## 2. 방어 게이트 3계층 (Deterministic 3-Tier Gates)

### [1층 실행 게이트 (PreToolUse Gate)]
- **문이 서는 곳**: 도구 및 명령이 실행되기 직전
- **막는 순간**: 위험한 일이나 무단 시공이 일어나기 전
- **확정 장치**:
  - 대표님의 명시적 승인 화이트리스트 키워드(`시공해`, `진행해`, `배포해`, `수정해`, `적용해`, `실행해`)가 직접 채팅 발화에 없을 시 쓰기 도구 호출 즉시 자가 차단.
  - 비밀키(API Key, Secret)의 프론트엔드/클라이언트 코드 노출 시도 차단.
  - 계획/보고 요청 상태에서 쓰기 도구 진입 시 원천 봉쇄.

### [2층 커밋 게이트 (Commit Gate)]
- **문이 서는 곳**: Git 커밋이 실행되는 순간
- **막는 순간**: 나쁜 코드나 깨진 빌드가 저장소에 기록되기 전
- **확정 장치**:
  - `npm run build`를 사전 실행하여 0 Error가 확정 검증되지 않은 코드는 커밋 금지.
  - 타입/린트 에러가 단 1건이라도 존재할 경우 커밋 중단.

### [3층 배포/머지 게이트 (Deploy/Merge Gate)]
- **문이 서는 곳**: 서비스가 실서버에 나가고 합쳐지는 순간
- **막는 순간**: 사용자에게 결함이 노출되기 전
- **확정 장치**:
  - 실서버 배포 후 헤드리스 브라우저(Playwright)를 통한 PC(1920x1080), 태블릿(768x1024), 모바일(390x844) 다중 뷰포트 실측 캡처 필수.
  - 실제 HTTP 200 응답 및 레이아웃 깨짐/회귀 결함 0건이 증명되기 전에는 절대 완료("작업 완료") 선언 불가.

## 3. 데이터베이스 및 스키마 하향 안전망 (Backward Compatibility Guard)

> "컬럼 하나 추가해 달라고 했는데 이미 쌓여 있는 데이터에는... 멀쩡하던 앱이 없는 칸을 찾다가 멈추는 일이 있을 수 있다."

1. **레거시 데이터 크래시 원천 차단**:
   - 데이터베이스(Firestore, MySQL, Supabase 등)에 새로운 컬럼/필드를 추가하거나 스키마를 변경할 때, **기존에 이미 적재되어 있는 과거 데이터에는 해당 필드가 존재하지 않는다**는 사실을 불변의 전제로 둔다.
   - 새 필드를 조회하는 모든 프론트엔드/서버 코드는 반드시 **Optional Chaining(`?.`)**과 **기본 Fallback 기본값**을 강제한다:
     ```javascript
     // 올바른 예시:
     const title = data.clientTitle || data.clientName || '이름 없음';
     const items = data.answers?.items || [];
     ```
2. **스키마 마이그레이션 이력 보존**:
   - 스키마가 변경될 경우 변경 사유와 필드 매핑 규칙을 계획서 및 코드 주석에 기록한다.

---

## 4. Litmus Scope Guard (대규모 변경 임계값 통제)

- 소스코드 변경 범위가 **파일 3개 초과** 또는 **80줄 초과**인 대규모 시공의 경우:
  1. 한 번에 모든 코드를 일괄 변경하지 않는다.
  2. 사전 테스트/검증 계획을 명확히 수립하고 분할 시공한다.
  3. 시공 중간중간 2층(빌드) 게이트를 통과시키며 단계별 확정성을 확보한다.
